\section{Discussion}
\label{sec:discussion}

The safety results in this version are interim (one seed, four of five configurations) and the memory
results are a pilot, so what follows separates what the data show from the questions the remaining runs
are built to answer.

\paragraph{A benchmark can only measure defences above its floor.} On the AgentDojo subsample, the
undefended ternary agent acted on an injection in 3 of 120 trials, and only on a goal satisfied by text.
Every configuration then sits at the floor, and no reviewer can show a benefit. This is a property of the
agent--benchmark pairing, not evidence that the reviewers are unnecessary: static benchmark cases
understate what an adaptive attacker achieves~\citep{narisetty2026adaptive}, and a more capable or more
compliant agent would raise the floor. The next steps follow directly: run the whole of each AgentDojo
suite rather than the first five tasks, add the standard-quantisation agent, and use more seeds, so that
the undefended attack success rate is large enough to measure a reduction.

\paragraph{Gates on tool calls cannot see text-only goals.} The only successful case asks the agent to
recommend a particular hotel in its reply. Jig's defences, like most out-of-band defences, act on tool
calls, so a goal reached through the agent's words passes every configuration, including read-only mode.
For an always-on agent that reports to its owner unattended, persuasion through the report is a real
channel; reviewing outbound \emph{messages} as well as tool calls is a design question the paper will
return to.

\paragraph{Incidental rules shape results.} Jig's core URL rule, which refuses addresses without a
scheme, accounted for most refusals in every configuration because AgentDojo's Slack suite writes bare
host names. Comparisons between reviewers are therefore only meaningful alongside a per-layer account of
what was refused, which the harness now records for every blocked call. The account did more than
explain the numbers: it exposed a usability bug in the rule itself, now fixed in Jig. This is a modest
argument for running published benchmarks through the real product rather than through an idealised
harness.

\paragraph{Cost is where the configurations differ.} With security at the floor, the measurable
differences are in utility and approvals: Granite Guardian, prompted with a criterion written for this
programme (Appendix~\ref{app:guardian}), refused enough legitimate calls to cost about 18 points of
utility; Jig's Sentinel on the agent's own model cost none but asked the owner about one call in three
tasks. Which of these an owner should prefer depends on how attentive they are to approvals, which is why
approvals per task is reported beside every rate~\citep{yu2026habituation}.

\paragraph{Why measure memory in model tokens, not just accuracy.} On a shared consumer GPU the scarce
resource is context and compute, not disk. A strategy that answers well by carrying every past session is
not viable if it spends tens of thousands of prompt tokens per question. By recording the prompt tokens of
every ingestion, consolidation and answering call, the harness lets accuracy be read against its true
cost, which is where retrieval and agent-curated consolidation are expected to separate from full context
and rolling summaries~\citep{wu2024longmemeval,chhikara2025mem0}.

\paragraph{Forgetting is a trade-off, not a feature.} Consolidation that deletes superseded facts should
help on knowledge-update questions, where a stale fact is actively wrong, but hurt on temporal-reasoning
questions, where the history is the answer~\citep{uddin2026memora,kwon2026manufactured}. Reporting both
question types separately, with and without forgetting, is how the living benchmark surfaces that tension
rather than hiding it in an average.

\paragraph{Measuring defences without authoring attacks.} The safety evaluation deliberately uses only
published benchmarks~\citep{debenedetti2024agentdojo,zhan2024injecagent}, run unchanged through a Jig
adapter. This bounds what can be claimed---static benchmark cases are an upper bound on robustness, and
adaptive attacks break most out-of-band defences~\citep{narisetty2026adaptive}---but it keeps the
programme on established, reviewable ground and makes every safety number reproducible against a public
artefact. The reviewer conditions (none, rules only, the agent's own model, a smaller different-family
model, read-only mode) are exactly the choices a Jig owner can make, so the result is directly actionable.

\paragraph{Approval burden is a first-class measure.} Rules and reviewers can achieve coverage by asking
rather than blocking, and an owner who approves whatever is queued gains little from an
``ask''~\citep{yu2026habituation,kumar2026loopjacking}. The harness therefore reports approvals per task
alongside every catch rate, so reviewers are compared on what they \emph{block}.

\paragraph{Recommendations for Jig, to be tested.} Motivated by prior work rather than by results here, the
queued runs probe four design ideas: (1) exposing memory and note provenance to the
Sentinel~\citep{zhan2026authmem}; (2) applying the same provenance or review to every persistent channel
the agent can write unattended and read back later (memories, notes, files, task results); (3) a
deterministic check that flags a private memory value appearing in any outbound argument, including request
headers~\citep{lan2026silentegress,fan2026pact}; and (4) letting a task carry a simulated clock and letting
evaluations map benchmark host names to local services without an in-process exemption.
