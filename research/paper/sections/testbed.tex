\section{Testbed}
\label{sec:testbed}

\paragraph{Jig.} The harness drives Jig's public Python API (the runtime, its task scheduler, its
executor and its memory store) and does not modify Jig's code. Each trial runs in a fresh Jig instance
with its own data directory, so no memory leaks between trials.

\paragraph{Models and hardware.} One NVIDIA RTX~5090 (32~GB), shared with the owner's own model server.
The agent is Bonsai~2~27B (ternary PTQ1\_0, about 1.75 bits per weight) on the owner's llama.cpp server,
used only through its API. The pilot judge is Granite~4.2~8B; the full run's judge is Gemma~4~26B-A4B, a
different family from the agent. Qwen3.8-27B at Q4\_K\_M is the standard-quantisation counterpart of the
agent, and the small models and Granite Guardian~4.1~8B are candidates for the reviewer study of
Section~\ref{sec:safety}. All are Apache-2.0; Table~\ref{tab:models} lists files and checksums.
Harness-started servers use their own ports, are refused if they would leave less than 2~GiB of free
video memory, and are tied to the harness process so that they stop with it however it exits.
